# BezierWall2D 后续改进方案

## 建议顺序

1. **先缩短改墙的循环。** 打通草稿和场景墙的原位更新，再把成品叠到描点底图上，补齐保形插点、吸附和撤销。
2. **再完善关卡编辑。** 统一墙线采样，让多个门洞、闭环上的缺口、摆件避让和接墙后的门洞位置使用同一份距离数据。
3. **最后处理更复杂的画面。** 先用可移动角色验证遮挡，再加卡通质感和参考图辅助描点。

当前工程基于 Unity 2022.3.62f2。露台示例已经覆盖圆角直线、门洞、沿墙灯笼、闭环花坛和同路径样式对照，花园示例可作为贝塞尔回归场景。[现有使用说明](../README.md)

## P0 · 草稿关联与原位更新

已实现。露台墙已关联到草稿，可在编辑器中直接试用「更新选中墙」。[原位更新使用说明](USER_GUIDE.md#关联草稿与原位更新)

此前调整墙体时需要重新烘焙，再换掉旧墙并补回场景引用、排序和摆件。原位更新将这一步改为在选中墙上应用草稿。

- **记录绑定。** 给每个烘焙实例保存草稿资产引用、场景对象标识，以及工具生成的 Mesh、材质、碰撞体和摆件容器。多个场景对象可以使用同一份草稿，各自持有烘焙输出。首版在已保存的场景中建立可跨重开的绑定。
- **验证后写入。** 先用现有生成逻辑算出网格、碰撞轮廓和摆件，样式切换也先在草稿副本上试算，避免增厚后挤坏小圆角。遇到这种情况，指明失败的拐角和可用的半径或墙厚。全部通过后再更新对应产物。保留场景对象身份、变换、父子关系、排序和手工添加的组件或子节点。用户指定的材质继续由用户管理。若要更新的 Mesh 还被其他墙引用，先为当前墙分配独立输出。
- **支持撤销和实际刷新。** 将一次更新做成一个 Undo 步骤，覆盖网格、碰撞与生成摆件。更新 Mesh 后检查 Game 视图是否立即使用新的顶面贴图和几何，并在保存重开后再次核对。生成失败时原墙仍可用。

**验收**

用露台墙切换砖墙和矮石墙样式，再改门洞宽度并原位更新。场景里只有一面目标墙，原引用仍有效。预览、碰撞和摆件同步变化，撤销、重做、保存重开都得到对应结果。[烘焙入口](../Assets/BezierWall/Editor/BezierWallAssets.cs)

## P0 · 描点时直接看到成品

- **底图叠加。** 在现有「描点」页增加可开关的半透明成品层，叠上墙脚轮廓、门洞切点和摆件位置。拖动点或控制柄时即时看到墙厚占用。显示给用户的路径和最终烘焙使用相同采样。
- **保形插点。** 贝塞尔模式在命中的曲线段上用 De Casteljau 分割，按分割结果写回两段控制柄。需要时将受影响的自动切线转为手动，避免插点后自动计算改变原曲线。圆角直线先支持在直段插点，预检查插点后的圆角退距，提示会改变圆角的操作。
- **对齐操作。** 加可开关的网格吸附和端点吸附。拖动到候选端点时显示目标及距离。接墙沿用当前的端点选择、方向反转和合并逻辑，界面负责显示合并预览和失败原因。

**验收**

在花园曲线上插点，前后轮廓在采样容差内重合。闭环首尾段也能插点。圆角墙调整点位时，厚度、门洞和摆件叠加结果与成品预览、烘焙一致。[编辑窗口](../Assets/BezierWall/Editor/BezierWallWindow.cs)

## P1 · 多个门洞与统一距离数据

现在一面墙保存一个门洞，闭环上的门洞需避开路径起点。当前画布、烘焙和摆件分别调用路径采样，扩展门洞前适合统一中心线和长度计算。

- **共享采样结果。** 一次计算坐标、累计弧长、切线和闭合信息。由它生成实体墙段、切口和原路径上的距离。网格、碰撞、摆件和画布都消费同一份切口结果。初期保持现有采样密度，先验证输出一致，再优化重复计算。
- **扩展为门洞列表。** 每个门洞有稳定标识、位置和宽度。旧草稿的单门洞字段读入后转换成一条记录。闭环跨起点的门洞在长度域里拆成两段处理，首尾合并后按实际缺口生成端盖。界面选中门洞后可以拖中心或调宽，相交门洞给出定位反馈。
- **保留关卡位置。** 默认沿用现有的百分比定位。增加以路径起点为基准的距离定位，适合需要固定在距墙头指定距离的门。接墙时用拼接前的切点和长度映射确定门洞在新路径上的位置，并在应用前显示结果。
- **摆件共用避让区。** 沿整条路径规划候选位置，以实际保留的门洞区间检查摆件占地。处理闭环首尾间距和跨起点的缺口，保留摆件与源 Prefab 的链接。

**验收**

两种路径各烘焙带两个门洞的墙。闭环另外测试一个跨起点的门洞。窗口标出的切点和烘焙一致，玩家大小的圆形投射能穿过每个门洞，墙段仍能阻挡，灯笼和柱子不占通道。旧草稿第一次打开时保持原门洞位置。[路径与切口逻辑](../Assets/BezierWall/Editor/BezierWallGeometry.cs)

## P1 · 角色遮挡与碰撞体验

目前一面墙用一个渲染排序顺序。长墙绕到角色前后时，同一排序值很难表达整条墙的遮挡关系。先用露台搭一个简易可移动角色验证问题，再决定引入分段排序的范围。

- **按墙脚分段排序。** 给长墙提供可选的排序分段，让每段用自己的墙脚参考点参与 Y 方向排序。分段取自共享采样点，接边复用顶点坐标并保持 UV 连续。保留门洞和墙的真实端盖。
- **保持碰撞连续。** 纯渲染分段沿用原来的碰撞轮廓。角色沿实体墙滑动时检查闭环接缝、接墙点和门洞边缘，避免加入只由渲染分段产生的碰撞边。
- **同步摆件排序。** 让柱子、灯笼跟随最近墙段的排序，同时保留 Prefab 内各子节点的相对顺序。

**验收**

角色从 U 形墙两端绕行并穿过露台门洞，能在墙前正常显示，在墙后正确遮挡。沿闭环外沿行走时接缝无穿漏、卡点或明显闪烁。

## P2 · 卡通外观与辅助描点

- **接触阴影和侧面明暗。** 用沿墙脚的窄条生成柔和接触阴影，在实际门洞处切断。侧面增加可调的上亮下暗，细描边作为可选项。把这些参数纳入样式预设，继续用露台同一路径对照砖墙和矮石墙。
- **辅助描点。** 首版针对轮廓清楚的透明图和黑白路径图，识别候选轮廓、简化点列，并让用户确认要描的是哪一条边。生成的点集进入现有窗口，仍可手动调整。优先验证开放线和单一闭合轮廓，再处理图案交叠和断线。
- **制作素材指引。** 补齐顶面与侧面贴图的平铺示例，以及柱子、灯笼的根节点原点、+X 朝向和占地半径示意。烘焙后保留可复用的 Prefab 和贴图引用。

## 回归与交付

每个阶段交付一个可直接在现有示例里试用的结果。先把关键验收固定成 Unity EditMode 测试，再给角色移动、碰撞及遮挡加一小组 PlayMode 用例。渲染行为用 Game 视图或实际渲染图核对。

- **几何。** 两种路径都覆盖开放与闭环、两段墙吸附、急弯与厚墙组合。检查接缝顶点、端盖、连续 UV 和碰撞轮廓。
- **兼容。** 用现有花园、露台、花坛和样式对照草稿回归。切换样式后仍保留描点、控制柄和门洞设置，既有共用贴图与独立顶面贴图的墙都能正确显示。
- **操作。** 覆盖插点、套用预设、接墙、原位更新的撤销和重做，并验证场景关闭重开时的草稿绑定与 Prefab 链接。
- **场景。** 保留露台作为综合案例，分别检查门洞通行、花坛中空、摆件避让和角色前后遮挡。

首个可交付版本以「选中露台墙，编辑草稿并原位更新」为准。完成这条流程后，继续做多门洞和排序分段时都能复用同一套更新与验证入口。
