# BezierWall2D 更新与优化方案

## 当前基线

工程使用 Unity 2022.3.62f2。贝塞尔、圆角直线、闭环、接墙、单门洞、沿墙摆件和样式预设均可用。露台负责综合验证，花园用于贝塞尔描点回归。[使用说明](USER_GUIDE.md)

草稿关联和原位更新已在 `abc6ac1` 完成。在露台选择 `Rounded Terrace Wall`，打开关联草稿后，可以修改描点、门洞和样式，再点击「更新选中墙」。已验证原墙引用、手工子节点和自定义材质，网格、分面贴图、碰撞和摆件可随一次撤销或重做恢复。共享网格会为选中墙分离独立输出，场景保存重开后关联仍有效。样式套用已在草稿副本上预检，圆角与墙厚冲突时会给出受限描点及可用半径。[原位更新操作](USER_GUIDE.md#关联草稿与原位更新) · [实现入口](../Assets/BezierWall/Editor/BezierWallBakeUpdates.cs)

## 建议实施顺序

1. **P0 · 缩短描点和试形的循环。** 先做共享路径结果和底图成品叠加，再交付贝塞尔保形插点和接墙预览。
2. **P1 · 完善门洞和摆件。** 在共享路径结果上扩展多个门洞、闭环跨起点缺口和接墙后的门洞映射。
3. **P1 · 验证实际走位和遮挡。** 先让角色在现有露台绕墙和过门，再为有需要的长墙增加分段排序。
4. **P2 · 丰富卡通表现。** 加接触阴影、侧面明暗和参考图辅助描点，继续用同一路径对照样式。

## P0 · 共享路径结果与底图叠加

现有描点画布、成品预览、烘焙和沿墙摆件各自调用采样或切口计算。同一次修改可能重复采样，增加预览成本，也让多门洞难以保持一致。

- **提取共享结果。** 在草稿副本上计算中心线、累计弧长、切线、闭合信息、切口和实体墙段。网格、碰撞轮廓、摆件和窗口读取同一结果。第一步保留现有采样密度和旧草稿字段，用花园和露台对照切点、轮廓及摆件姿态。
- **按实际修改刷新。** 描点、控制柄、圆角、闭合状态或门洞变更时，在下一次需要绘制时重算。平移、缩放和选择描点只更新画布，换颜色或贴图只更新外观。墙厚变动时重新检查内侧折叠与碰撞轮廓。让有效预览尽量复用已有 Mesh、材质和 Prefab 实例，只刷新受影响的部分。
- **叠在参考图上。** 在「描点」增加可调透明度的成品层，显示墙体投影、门洞和摆件。沿用现有画布坐标及正交投影。拖动时更新窗口预览，点击「更新选中墙」时应用到已关联的场景对象。

**验收**

在花园拖动贝塞尔点，在露台调圆角和门洞。底图上的墙体、切口与成品预览及烘焙对齐。一次有效编辑只构建一次共享结果，空闲重绘、缩放和平移不触发重采样。无效草稿在画布标出原因及受限拐角，场景仍能显示上一次有效烘焙。[编辑窗口](../Assets/BezierWall/Editor/BezierWallWindow.cs) · [路径计算](../Assets/BezierWall/Editor/BezierWallGeometry.cs)

## P0 · 保形插点与对齐

- **贝塞尔插点。** 对命中的曲线段用 De Casteljau 分割，写回原有端点和新点的控制柄。必要时把受影响的自动切线改为手动，避免自动重算拉动原曲线。闭环首尾段也适用。
- **圆角直线插点。** 从未被圆角占用的直段开始。先试算插点后的圆角退距，保留原路径轮廓。插点会改变圆角时，在画布显示原因和可选位置。
- **吸附和接墙预览。** 增加可开关的网格与端点吸附，拖动时显示目标和距离。接墙继续使用当前的端点选择和方向反转逻辑，并在确认前显示合并后的路径与门洞。

**验收**

用花园开放曲线和贝塞尔闭环分别测试插点，包括闭环首尾段。对照分割前后等参数的曲线位置，确认轮廓重合。针对已带门洞的墙，在生成采样容差内比较切点位置与摆件朝向。插点、吸附和接墙分别可以一次撤销并重做。[接墙入口](../Assets/BezierWall/Editor/BezierWallJoins.cs)

## P1 · 多门洞与闭环缺口

- **将单门洞扩展为列表。** 每条记录有稳定标识、中心、宽度和定位方式。旧草稿在读取时转换成一条默认记录，首次打开时保持现有门洞位置。保留百分比定位，再增加按墙脚距离定位。
- **统一开口区间。** 由累计弧长算出门洞占用的区间。闭环跨起点时将区间拆成首尾两段，再按真正的开口边缘封端。相交或越界时标出对应门洞，供用户调整。
- **同步门洞、接墙和摆件。** 切口区间同时驱动网格、碰撞、画布和摆件避让。接墙时把原门洞映射到合并后的长度域。调整门洞后，能保留的摆件继续使用原 Prefab 实例。

**验收**

两种路径各做一面带两个门洞的墙，再做一面门洞跨起点的闭环。用角色尺寸的圆形投射检查可从每个门洞通过，墙段仍能阻挡。原位更新、撤销重做和重开仍能恢复同一套网格、碰撞和摆件。

## P1 · 角色遮挡与场景验证

- **先做可走动的露台对照。** 用一个简单角色跑通墙前、墙后、门洞和花坛外沿，记录当前单排序顺序会出错的位置。
- **按墙脚分段排序。** 给需要的长墙启用可选渲染分段，用各段的墙脚位置参与 Y 方向排序。接边沿用同一采样顶点和 UV，摆件跟随所在墙段，并保留 Prefab 内部的相对顺序。
- **碰撞按实体路径生成。** 纯排序分段共用原有碰撞轮廓。用实际移动测试闭环接缝、接墙点和门洞边缘，检查穿漏和卡点。

**验收**

角色绕过 U 形墙两端时前后遮挡正确，通过露台门洞时没有碰撞阻挡。沿花坛外沿行走时接缝连续。砖墙和矮石墙对照继续使用同一条路径。

## P2 · 卡通外观和参考图辅助

- **阴影与明暗。** 增加可选的墙脚接触阴影，沿实体墙段生成并在门洞处断开。侧面可调上亮下暗，细描边作为样式预设的选项。
- **辅助描点。** 先针对清楚的透明 PNG 或黑白参考图提取候选轮廓，让用户选边并生成可编辑描点。首版验证开放线和单一闭合轮廓。
- **素材示例。** 用露台对照演示顶面、侧面的独立平铺，用灯笼或柱子素材标示根节点、+X 方向和占地半径。

## 性能测量与回归

- **记录可复现的基线。** 在同一 Unity 版本下，用花园、露台和一条接近 500 个摆件候选位置的长闭环记录拖动预览、套用样式和原位更新。在 Unity Profiler 比较采样次数、操作耗时的中位数和 P95、GC 分配、资产依赖扫描次数及新建 Prefab 实例数。
- **优先减少确定的重复计算。** 先比较共享采样前后的结果和耗时，再做摆件增量预览和更新，复用仍匹配的实例，只创建缺少的位置。如果项目资产引用检查在较大工程里占主要耗时，再为保存的 Scene 和 Prefab 建引用索引，在导入、移动或删除时刷新。已加载场景中未保存的引用继续实时检查。
- **固定 EditMode 回归。** 覆盖两种路径、开放和闭环、接墙、单门洞旧数据、样式快照、共享网格分离、失败预检、撤销重做及场景重开。对更新前后的场景对象标识、Mesh 绑定和 Prefab 链接做比较。共享输出同时测已加载场景中的未保存引用，以及未加载的场景和 Prefab。
- **保留 PlayMode 和渲染检查。** 用物理投射和角色移动验证墙与门洞。实际渲染对比独立顶面贴图、角色遮挡以及撤销后的图像，覆盖 CPU 数据恢复到画面刷新的全过程。

下一次开发可以先交付「共享路径结果 + 描点底图成品叠加」。用露台完成一次「拖动描点 → 看见门洞和摆件变化 → 原位更新 → 单步撤销」作为验收，再继续扩展门洞列表。
